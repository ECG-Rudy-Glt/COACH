# Languages (i18n)

COACH ships in **French** (source language) and **English**. This page explains how texts are translated and how to add a language. The step-by-step recipe is in [`skills/add-language/SKILL.md`](../skills/add-language/SKILL.md).

## Principle: the French text is the key

Code stays readable and the French output is byte-identical: there are no message ids. A translation file maps the exact French text (or a *template* with holes) to its translation:

```json
{ "Accueil": "Home", "Dans {days} jours": "In {days} days", "{total} exercice{v}": "{total} exercise{v}" }
```

`app/static/i18n/<lang>.json` is the **single dictionary**, shared by the browser (`app/static/i18n.js`, loaded before `app.js`) and the server (`app/i18n.py`). A text without translation stays in French. Lookup order:

1. exact match;
2. template match, most specific first. Holes: `{name}` (anything), `{v}` (optional suffix, e.g. the plural "s"), `{num}`, `{num2}`… (a number only). The value captured by a hole is translated in turn;
3. composed texts: split on sentences / ` · ` / ` — ` / line breaks, then on commas and ` + `, translating each known piece.

The browser calls `__("Dans {days} jours", { days })` (explicit template) and `h()`/`toast()`/accessibility attributes translate every string they receive, so tables of labels and texts coming from the server are translated without touching each call site. **Server texts that are stored (plan titles, notes, advice, chat) stay French in the database and are translated when displayed**, so switching language also translates the history.

## Where the language comes from

| What | How |
|---|---|
| Interface | `localStorage.lang`, else the account language, else the browser language (English for an unsupported one). Language selector: login screen and *Profile → Language*; changing it reloads the screen. |
| Requests | the interface sends `X-Lang` on every call; the server also reads `?lang=`, then `Accept-Language`, then the `LOCALE` environment variable (default `fr`). `app.i18n.current()` returns it. |
| Account | `users.lang` (migration 0013), set by `PUT /auth/language`, returned by `/auth/me` and the login. Used by background jobs (notifications, weekly e-mail) through `i18n.use(lang)`. |

## What is translated, where

| Layer | Mechanism |
|---|---|
| UI texts | `app/static/i18n/en.json`. `python scripts/i18n_check.py` lists the literals of `app.js` without translation (also run by the tests). |
| Questionnaire | `questions/i18n/<lang>/*.yaml`: question text, help, unit, option labels (stored values stay French), entry-field labels and options. `GET /bank?lang=en` and the question endpoints return the localized bank; ids, `fact_key`, option values and `show_if` never change. `benchmarks.yaml` translates the *My performances* page. |
| Engine texts (plan, nutrition, advice, errors) | the same dictionary, applied when displayed. They are f-strings in the engine: the key is the f-string with `{name}` holes. |
| Push notifications and e-mails | `i18n.tr()` on the server, in the user's language. |
| LLM prompts | `data/prompts/<lang>.yaml` (review, chat, intake, check-in, digest, meal); French prompts stay in the code. Each prompt states the answer language (`LANGUAGE:` line). A language without prompt gets the French prompt plus an explicit "write in <language>" rule, and every LLM call appends that rule when the prompt has none (`prompts.with_language`), including the meal estimate. JSON keys, rule ids and action names are never translated. |

## Adding a language

1. `app/i18n.py`: add the code to `SUPPORTED` and its name to `LANG_NAMES`; `app/static/i18n.js`: add it to `LOCALES` (BCP 47 tag used for dates); migration for `users.lang` CHECK if needed.
2. Create `app/static/i18n/<lang>.json` (start from `en.json`; keep the holes), `questions/i18n/<lang>/*.yaml` and `data/prompts/<lang>.yaml`; add the file to `SHELL` in `sw.js` and bump the cache name.
3. Run `pytest tests/test_i18n.py`: it checks that every UI text, every question and option, the benchmarks, the engine texts and the prompts are translated, and that the browser and the server translate identically.

## Known limits

- Evidence summaries (`finding_fr`, `limits_fr` in `data/evidence/*.yaml`) are shown in French in every language (add `finding_en` / `limits_en` and fall back to French).
- Health wording (red flags, disclaimers, pain advice) should be reviewed by a native speaker.
- Units are metric only (conversion would happen at display, storage stays metric). Exercise names come from the library (English by origin).
- A template with a hole captures anything: keep the fixed part of a template distinctive, and use `{num}` for numbers.
